# 1000 题并行生产

> 此文包含早期 K8s / Sol 运行记录。当前默认已改为本地渲染，模型/provider可替换；现行配置以 [README](../README.md)、[模型接口](MODEL_INTERFACE.md)、[渲染后端](RENDERING.md)为准。历史批次保留原协议。

目标是 1000 个完整的中等题交付。场景初筛通过、生成自评、原闭环通过、处理中和失败都不直接计入目标。原闭环后还会自动做交付模型审核，检查题目能否在自由移动的 3D 世界中唯一定位、方位是否固定、题干是否泄露答案、初始是否有实际遮挡及答案证据是否充分。文字或已有视角可修复时，再做至多两次定点返修和看图回答、复审；需要重建场景或不可修复时剔除。只有最终审核通过且交付文件完整才计数。同源 GLB 在不同队列中的重复不重复计数。审核并非人工标注或程序对语义答案的证明。

## 运行

```bash
python -m pip install '.[batch]'
export LUNA_API_KEY=你的密钥
python tools/prepare_batch_sources.py --out /data/production1000/sources \
  --shards 4
python tools/scene_production_batch.py --out /data/production1000 \
  --target 1000 --parallel 4 --batch-size 4
```

第一步只下载公开元数据 Parquet 和 GLB 路径索引，不下载全部原生资产，也不加载三维几何。程序先保留原始作者、许可证、下载 URL 及元数据快照哈希，只限制过大、来源/许可不符或没有实际 GLB 归档路径的条目，不再按类别或标题判断质量。按类别打乱，再将每类均匀分给四条队列，保证分片无重复、不会让某条队列只有同一种场景。来源中各类别总量不相等，不能保证最终各类别交付量相等。

面数、材质数、纹理数、标题关键词和类别的质量门槛均已取消。单 GLB 上限默认35 MiB，文件有效性与去重检查保留。场景下载和K8s取景后，统一由v4模型判断完整物件、类别和区域的丰富度，拟保留必须追加局部3D取证。来源准备数量不是好场景数量。旧几何/材质参数仅兼容接受，不参与筛选。

新的来源准备协议与旧协议分开；从原始元数据准备新的 `sources/` 和生产目录，不能直接复用被旧规则裁剪过的清单来宣称完成新规则筛选。

第二步冻结当前程序及提示词快照，启动四个持久的独立生产进程。每个进程按原有闭环顺序下载、远程渲染、留删、增强、回答、审核、返修。每条队列筛选和出题复用一个 GPU pod，通常四条队列占用四个 GPU，不在本地渲染。worker 不再在八小时后自行退出；每次远程任务复制完产物后清理自己创建的临时目录。

## 自动恢复与停止

模型及下载层保留 429／5xx 重试。某条队列因接口、集群或处理异常退出时，监督程序延迟后用原目录及 `--retry-failed` 自动恢复，默认每条队列最多 20 次恢复。过去的质量剔除不重新询问；未改变题目及证据的审核意见保持缓存，不采样到 PASS 为止。

监督程序每 15 秒更新总进度，仅汇总内容哈希校验通过的实际交付。总交付达到 1000 后通知所有队列有序停止，并清理本次四个 worker。可能有少量同时完成的额外交付，也保留，不丢弃。

交付审核用两个并发的模型任务独立消费原闭环通过的结果；它不占本地或集群渲染 GPU。交付层的文字／已有视角返修复用真实产物，只复制和链接文件，不在本地加载或渲染三维几何。模型重新看图给答案，程序只核验文件格式、字段和哈希。任何原样题图的有效审核结果都被缓存；返修必须改变实际题目或选定视角，而不是不断重问直到 PASS。

若有八张可用 GPU，新任务可以直接把准备清单的 `--shards` 和生产的 `--parallel` 都设为 8，并加 `--delivery-review-parallel 4`。现有四队列任务也支持扩容：先停止监督程序和生产进程，保存原断点，再以 `--scale-out --parallel 8 --delivery-review-parallel 4` 启动原目录。程序只在尚未扫描的、整页边界处拆分清单；原清单和代码快照都不改动，原队列的处理数量预算缩到前半部分，新增四条队列只处理后半部分。所有 UID 仍互斥，总素材数不增加，已完成的题目继续交付。若后半部分已被扫描、队列仍运行、清单过滤条件不符或文件发生变化，会拒绝扩容，避免重复出题。扩容方案和新增清单的哈希保存在 `production.json` 的 `source_partition` 中。后续恢复不需要再次传 `--scale-out`。

目标、地标可以在探索后才被发现，不要求它们出现在初始图。“面对壁炉”“从初始相机方向看”等固定参照可用；未给解题者某张“揭示截图”却要求回答其画面左／右不可用。审核协议及代码有独立版本快照。明确的协议升级使用 `--advance-delivery-review`，保留旧协议记录，不将不同版本的意见合并成同一个接受率。

磁盘空间低于默认 20 GiB、所有来源耗尽或所有可用队列阻塞时，保存断点并明确停止。这些状态不是目标完成，也不会降低质量标准凑数。每条队列的来源在启动前冻结，不能事后悄悄追加或改变筛选标准。素材耗尽不足 1000 时，应新增来源批次并保留已有结果的来源记录。

收到 SIGINT／SIGTERM 后，会先通知生产进程保存断点和释放自己的 worker，再退出。再次执行同一命令可以恢复。若监督程序意外退出而生产进程仍活着，重启后根据进程命令中的实际输出路径接管，避免再起一份重复生产。

## 输出

```text
production1000/
  production.json / launcher.json / supervisor.log
  progress.json / summary.json / gallery.html
  keep.jsonl / reject.jsonl / failed.jsonl / delivery.jsonl
  delivery/<uid>/
    scene.glb / question.json / start.png / reveal.png / audit.json
    navigation_audit.json / provenance.json
  delivery_history/                平铺交付中被新修订替换的旧版本
  delivery_reviews/                交付审核、定点返修及版本记录
  sources/                         冻结来源池和四份互斥清单
  sources_scaleout/                可选的扩容后半段清单及原始清单分割记录
  workflow_snapshot/               生产代码和提示词快照
  shards/shard-01/ ... shard-04/    原始筛选、生成、返修记录
```

图册直接在初始／揭示图片下方展示原题和模型答案，并提供 GLB、相机与审核记录下载。`provenance.json` 保留原始来源、作者、许可证与所在队列。`navigation_audit.json` 是最终交付审核及返修历史，`audit.json` 保存该交付文件对应的审核证据。待交付审核及模型处理失败的条目不记入保留数。
